# Do Androids Dream of a Dead Internet: Interactive Watermarks for Bot Detection Code Base

This code base for "Do Androids Dream of a Dead Internet: Interactive Watermarks for Bot Detection" demonstrates a method for steganography using Large Language Models (LLMs). 
In this work, we study watermarking protocols in an interactive setting. We propose an interactive, publicly verifiable watermarking scheme we call prompt poisoning.
In our construction a user steganographically encodes key material into text that they expect to become part of the prompt that is issued to an LLM. 
The LLM provider can detect the key material and include an undetectable symmetric watermark in its response, which can be verified only by the originating user. Critically, the bot 
cannot detect the presence of either the "poison" prompt or the resulting watermark. 

It embeds a hidden cryptographically generated bitstring into the text generated by an LLM using **Rejection Sampling**. It ensures that the generated text remains coherent while mathematically encoding hidden data that can be perfectly recovered using the same tokenizer.

# LLM Steganography: Embed & Decode (test_embed_decode.py)

This script demonstrates a method for steganography using Large Language Models (LLMs). It embeds a hidden cryptographically generated bitstring into the text generated by an LLM using **Rejection Sampling**. It ensures that the generated text remains coherent while mathematically encoding hidden data that can be perfectly recovered using the same tokenizer.

## Features
* **Rejection Sampling Embedding:** Generates text where specific chunks of tokens hash to target bits.
* **Entropy Thresholding:** Ensures hidden bits are only embedded in high-entropy (unpredictable) parts of the text to maintain stealth.
* **Tokenization Stability:** Verifies that generated text survives re-tokenization without altering the hidden message.
* **Verification:** Automatically attempts to decode the generated message to verify data integrity.
* **Perplexity Analysis:** Calculates the perplexity of the generated text to measure quality/detectability.

## Usage

The basic syntax requires only the model path (or HuggingFace Model ID).

```bash
python test_embed_decode.py <model_path> [options]

```

### Example

Run with a Qwen2-0.5B-Instruct model (CPU friendly):

```bash
python test_embed_decode.py Qwen/Qwen2-0.5B-Instruct --tokens-per-bit-arg 4 --entropy-threshold 1.0 --cpu

```

Run with Mistral-7B-Instruct-v0.3:

```bash
python mistralai/Mistral-7B-Instruct-v0.3 --tokens-per-bit-arg 4  --max-memory 7.25GiB  --entropy-threshold 1.0 --quiet

```

## Command Line Arguments

### Positional Arguments

| Argument | Description |
| --- | --- |
| `model_path` | **Required.** The local path to the model or the HuggingFace Model ID. |

### Generation & Embedding Options

| Flag | Default | Description |
| --- | --- | --- |
| `--prompt`, `-p` | *Alvarez hypothesis...* | The initial context prompt for the generation. |
| `--tokens-per-bit-arg` | `8` | How many tokens make up one "chunk" that encodes a single bit. Higher values generally improve text quality but reduce data density. |
| `--entropy-threshold` | `10.0` | Minimum entropy required for a chunk to be accepted for embedding. Higher thresholds make the hidden data harder to detect but harder to embed. |
| `--target-output-tokens` | `None` | Forces the output to be a specific length. If the message is short, the script will generate unbiased "filler" text to meet this length. |

### Model Loading & Hardware

| Flag | Description |
| --- | --- |
| `--load-in-4bit` | Load the model with 4-bit quantization (requires GPU & `bitsandbytes`). Drastic memory reduction. |
| `--load-in-8bit` | Load the model with 8-bit quantization. |
| `--cpu` | Force execution on CPU. Useful for small models or debugging without CUDA. |
| `--max-memory` | Limit GPU memory usage (e.g., `'9GiB'`). Useful for multi-gpu setups or leaving VRAM overhead. |
| `--compile` | Uses `torch.compile` to optimize the model. (May increase startup time). |

### Sampling Parameters

| Flag | Default | Description |
| --- | --- | --- |
| `--temperature` | `1.0` | Sampling temperature. |
| `--top-p` | `1.0` | Nucleus sampling probability. |

### Output & Debugging

| Flag | Description |
| --- | --- |
| `--quiet`, `-q` | Suppress real-time terminal output (progress bars and generated tokens). |
